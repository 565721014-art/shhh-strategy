# 任意新题分析协议

## 一、引擎的目标

给定一份从未出现过的新赛题，Codex应当利用往年国一论文中可迁移的分析纪律，独立完成：准确读题、识别结构、建立母模型、判断各问依赖、提出可执行模型路线、设计验证、预警风险并给出论文表达方案。

它不应先猜“这像哪一年的哪道题”。正确顺序是：

> 新题事实 → 结构指纹 → 推理组件 → 组合路线 → 国一证据校验。

旧题只能证明某个组件曾经有效，不能替代对新题事实的分析。

### 迁移优先级

1. 第一优先迁移的是读题纪律：事实分层、信息时点、母问题识别、问题递进、瓶颈诊断与验证闭环。
2. 第二优先迁移的是结构组件，但只有在它能从新题事实独立推导出来时才可使用。
3. 具体模型、算法、目标权重和参数只作为备选工具，不因国一论文使用过就自动获得优先权。

若能从同一组新题事实推出更贴题、更可实现或更容易验证的方案，应优先采用改进方案，并说明它相对基线改进了什么、增加了什么风险、如何验证。

## 二、禁止行为

1. 禁止按行业名、名词或故事背景直接匹配旧题。
2. 禁止把整道新题强制归入唯一题型；结构分类必须允许多标签。
3. 禁止先选算法再解释题目。
4. 禁止把国一论文结论视为无需审计的标准答案。
5. 禁止在题目没有支持时添加旧题特有假设、变量或约束。
6. 禁止用“可采用遗传算法、神经网络”等算法清单代替模型结构。
7. 禁止只输出宏观套路；每一判断都必须落实到新题中的具体对象、字段、时间和交付物。
8. 禁止把“学习国一思路”等同于复用国一模型；具体算法没有继承优先权。

## 三、第一阶段：逐字建立事实层

在任何类比前完成以下六张表。若原题没有给出某项，标记“未知/需假设”，不能自行脑补。

这里的“六张表”是内部思考覆盖范围，不是每次都要向用户输出六张正式表格。实际做题时可合并成简短工作笔记；只有出现语义歧义、信息泄漏、约束冲突或路线分叉时，才展开相应部分并请求核对。

### 1. 交付物表

逐问记录：要求的对象、时间/空间粒度、数值或文件格式、精度、是否要求解释/检验/评价，以及是否必须沿用前问。

### 2. 题意语义表

圈出并解释所有关键动词和量词：建立、分析、预测、判定、优化、尽可能、至少、任意、首次、实时、调整、影响、评价。明确它们对应关系模型、概率、目标、硬约束、全称约束、事件或因果问题中的哪一种。

### 3. 对象与关系表

明确实体、连接关系和层级。例如人—多次检测、供应商—周—运输商、节点—边、运动体—路径、样品—重复光谱。不能只写字段名。

### 4. 变量角色表

分成给定参数、观测量、状态量、决策量、待估参数、不确定量和输出指标。若一个量在不同问中改变角色，逐问说明。

### 5. 信息时点表

对每个决策标明做出时已经知道什么、什么尚未发生。任何预测或决策使用未来信息，均视为致命泄漏。

### 6. 约束证据表

记录每条硬约束、软约束、优先级和来源。来自题目、物理规律、业务常识和人为假设的约束必须分开标注。

## 四、第二阶段：生成结构指纹

进入本阶段前，必须完整执行 [读题理解深度审计](读题理解深度审计.md)，取得“理解证书”。六张事实表只是材料覆盖证明，不能替代以下深度责任：替代解释树、代表对象生命周期、最小动作链复演、阶段与边界地图、信息能力阶梯、目标—代理—诊断分账以及从交付物反推状态。未通过时只能保留暂定理解和分支路线，不得用统一母模型提前抹平题目特异性。

不要只给一个“题型”。对新题在下列八个轴上多选并给证据。

### 轴一：任务动作

- 关系解释；
- 参数估计/反演；
- 预测；
- 分类/识别；
- 评价/排序；
- 优化/配置；
- 路径/调度；
- 控制/在线更新；
- 方案效果评价；
- 实验设计。

### 轴二：数据对象

- 无数据纯机理；
- 横截面；
- 时间序列；
- 面板/重复测量；
- 实验组合；
- 网络；
- 空间场/轨迹；
- 光谱/图像/信号；
- 成分/比例数据；
- 事件日志。

### 轴三：系统演化

- 静态；
- 连续时间动态；
- 离散期状态转移；
- 离散事件；
- 时变网络；
- 事件触发重优化。

### 轴四：信息与不确定性

- 参数已知；
- 参数由数据校准；
- 观测含噪；
- 未来随机；
- 部分可观测；
- 分布会漂移；
- 决策可获取额外信息。

### 轴五：决策变量

- 无决策，仅解释；
- 连续；
- 整数/二元；
- 混合；
- 路径/排列；
- 函数或控制序列；
- 分组边界/阈值；
- 多主体任务分配。

### 轴六：目标结构

- 单目标；
- 多目标权衡；
- 字典序优先级；
- 风险约束；
- 最坏情景；
- 概率/首次事件；
- 可行性优先。

### 轴七：主要证据

- 守恒/物理定律；
- 几何不变量；
- 概率机制；
- 实验比较；
- 历史预测表现；
- 因果/反事实；
- 专家或制度规则；
- 混合证据。

### 轴八：验证责任

- 量纲与边界；
- 守恒与不变量；
- 参数可辨识；
- 主体外/时间外验证；
- 约束逐项审计；
- 连续事件完整性；
- 不确定性传播；
- 因果稳健性；
- 算法最优性或复算。

最终以一句结构描述收束，例如：

> 本题是“重复测量的纵向关系 + 区间首次事件 + 分组阈值决策 + 不平衡分类”，而不是笼统的“医疗数据题”。

## 五、第三阶段：建立问题依赖图

逐问判断相对前问发生了哪一种变化：

1. 参数由给定变为待估；
2. 对象从单体扩展为多体；
3. 维度从二维扩展为三维；
4. 目标从计算变为优化；
5. 约束增加；
6. 信息从确定变为随机；
7. 系统从静态变为动态/在线；
8. 场景或材料改变，需要模型诊断；
9. 由预测转入决策；
10. 由方案生成转入效果评价。

寻找能被后续复用的最小计算引擎，即母模型。母模型不是某个算法，而是把输入、状态、约束和输出闭合的关系系统。

## 六、第四阶段：组合模型组件

从组件库选择两到五个组件。每个组件必须说明：

- 它由新题哪条事实触发；
- 它解决哪一个子问题；
- 输入和输出是什么；
- 与其他组件怎样连接；
- 哪些条件不满足时不能使用；
- 如何验证。

常见组合不是“单一模型”，而是：

- 机理正向模型 → 参数反演 → 约束优化；
- 数据清洗/特征 → 预测概率 → 经营决策 → 误差传播；
- 状态传播 → 时变网络 → 在线路径；
- 实验响应 → 候选最优 → 补充实验；
- 信号预处理 → 阶段/特征 → 分类或评价；
- 概率区域 → 数值积分 → 参数/阵列优化；
- 多期状态转移 → 混合规划 → 随机场景风险。

组件初选后必须执行 [置信度、冲突与缺失信息协议](置信度_冲突与缺失信息协议.md)：为每个候选记录支持事实、反证、缺失信息和置信度。行业背景或关键词不能计作组件支持证据；存在未来信息泄漏、变量角色冲突或硬约束不可行时，候选路线必须暂停。

## 七、第五阶段：提出双层路线

### 基线路线

必须简单、可解释、可运行，用于验证数据和主逻辑。基线不必最终最好，但必须能回答题目核心。

### 升级路线

只在基线明确违反某个结构时升级。例如个体内相关显著才升级混合效应，未来随机显著才升级随机规划，连续碰撞可能漏检才加入事件求根。每次升级必须说明修复了什么缺陷。

## 八、第六阶段：预先设计验证

在求解前给每个组件指定验证方式。至少包括：

1. 一个手算或特殊情形；
2. 一个结构验证（量纲、守恒、边界、不变量）；
3. 一个样本外/场景外验证；
4. 一个最终方案约束审计；
5. 一个参数或误差敏感性；
6. 若使用启发式算法，再加入精确小规模基线或独立算法复算。

## 九、国一证据的正确调用方式

只有结构路线形成后，才读取证据层：

1. 在迁移矩阵中找到匹配的组件，而不是匹配题名；
2. 从两到四个不同背景旧题中取证，避免被单题做法绑架；
3. 只迁移结构和验证，不迁移旧题专属参数；
4. 若国一方案之间分歧，保留多个候选并说明选择条件；
5. 最后做一次“去旧题化”：删除所有无法由新题事实支持的旧题痕迹。

再做一次“删证据测试”：暂时删去全部往年题名后，检查新题的变量、方程、目标、约束和验证是否仍能由新题事实独立成立；不能成立说明发生了照搬。

若存在同题高水平论文、官方讲评或可靠复盘，再执行深度审计中的“同题高水平方案对抗审计”：优先比较三份以上相互独立材料，且必须把“读题理解差异”与“求解方法差异”分开。发现遗漏时，先把无题名、无常数、可跨题复用的机制写回通用协议，再修当前题；禁止只记住该题的具体配置、模型或答案。

## 十、Codex执行口令

当用户给出新题时，Codex必须执行：

> 先独立解析新题事实并生成八轴结构指纹，不按年份或题名直接类比。建立各问依赖图和母模型，选择可组合推理组件，给出基线与升级路线、变量角色、目标约束、验证和写作结构。之后再从国一经验迁移矩阵中选择至少两个结构相似而背景不同的证据案例，用来校验而不是替代新题分析。明确所有不确定、假设和可能误配之处。

这里的“独立解析完成”以 [读题理解深度审计](读题理解深度审计.md) 的理解证书为准，而不是以六张表是否出现为准。

执行前从 [从这里开始：给 Codex 的新题入口](从这里开始_给Codex.md) 进入；执行后用 [对抗性误判测试](对抗性误判测试.md) 检查是否被背景词、算法词或缺失材料诱导。
