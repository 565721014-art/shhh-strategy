# 复杂度、证据与停止门

## 一、总原则：只删不合适的复杂度

模型更复杂并不自动构成创新，但复杂也不等于错误。每增加一个参数、模块、算法或假设，都应修复一个被题面、附件、数学反例或独立验证支持的缺陷，或承担不可替代的交付、结构裁决、互证、稳健性任务。能说清必要作用并通过后续准入的复杂度应保留；只有无法说明作用或证据不足的部分才删除。

规则库只用于发现风险，不等于所有规则都要在每道题中展开。未被题面事实触发的规则保持休眠，不进入分析、求解或论文。

### 先区分四种复杂度，不能一起删

1. **机制/表示复杂度**：状态数、空间维度、模式切换、网络结构、对象异质性。若由题面硬结构决定，必须保留。
2. **统计/参数复杂度**：待拟合参数、特征筛选、模型容量、超参数。它直接受有效样本、噪声与支持域限制。
3. **求解器复杂度**：全局搜索、局部精化、精确算法、启发式算法、独立复算。它由目标地形、离散规模和最优性要求决定，不能因样本少而自动删除，但必须共用同一合法模型与评价器。
4. **表达复杂度**：正文中的模型数量、符号、图表和分支。它由交付物和论证作用决定；可以压缩表达，不能反向删除求解所需结构。

必须先判断复杂度属于哪一层，再使用相应证据门。不能因为统计样本少而删除题面要求的物理状态，也不能因为求解器很高级就默认允许额外拟合参数。

## 二、每个机制必须提交题面触发证据

任何新增机制先写一行触发记录：

| 字段 | 要求 |
|---|---|
| 交付块 | 它服务于哪一问、哪个输出 |
| 原始证据 | 题面原句、图示关系、附件字段或可复核数据现象 |
| 基准缺陷 | 不加入该机制会具体漏掉什么、违反什么或产生什么反例 |
| 最小修复 | 只增加哪一个必要结构 |
| 反证条件 | 出现什么证据就撤销该机制 |

仅有“往年论文用过”“模型更先进”“可能存在”或“可以进一步考虑”不能触发升级。数据现象若是在反复试模后才发现，只能作为探索证据，必须在独立数据或外层验证中复核。

## 三、复杂路线六项准入门：必须全部通过

### 1. 触发门

存在可定位的题面、附件、数学结构或独立数据证据，而不是凭模型偏好添加。

### 2. 必要门

可信基准存在实质缺陷：无法生成必需输出、违反硬约束、不可辨识、遗漏关键状态，或在预先确定的主要评价上明显失效。若基准已足够回答题目，只允许停止，不允许为了显得高级而升级。

### 3. 数据承载门

先按独立对象、批次、时段或实验单元计算有效样本，而不是把重复行当新信息。检查缺失、噪声、类别/事件数、支持域、参数可辨识性和重采样稳定性。若无法说明数据能够区分新增自由度，复杂路线只能是`诊断性`，不能成为主结论。

参数个数不是唯一复杂度：树深、超参数搜索、特征筛选、神经网络容量、仿真校准自由度和人为权重都计入。有效独立信息不足时，优先使用降维、正则、部分识别、区间或情景分析，而不是继续加模型。

本门只限制需要从数据识别或调节的自由度。由几何、守恒、动力学、逻辑约束或输出模板直接确定的必要状态不得因“样本少”被删；它们改由公式闭合、边界情形、数值收敛和独立复算验证。若机理模型同时含待校准参数，则只收缩不可承载的参数部分，不删除题面强制的机理骨架。

### 4. 公平比较门

基准与候选必须使用相同的决策时信息、数据划分、目标输出、约束、评价分母和测试口径；训练型预处理都只能在训练折内拟合。若候选用了更多字段、更多未来信息或更宽松约束，应标为不同信息方案，不能写成算法优越。

基准不能故意做弱。至少包含一个“最小可信基准”；当领域存在公认的强简单方案时，还要与该方案比较。基准也必须满足硬约束并能真实运行，否则比较无效。

### 5. 独立收益门

比较前冻结一个主要指标、一个实际有意义的改进阈值以及不允许恶化的约束/副指标。复杂路线必须在未参与选择的外层验证、时间外/主体外验证、独立情景或解析反例上稳定获益；只在训练分数、某一次划分或次要指标上更好不算通过。

若题目不是数据拟合问题，收益可以表现为修复不可行、补上遗漏事件、获得正确下界或满足原先违反的硬约束，不强求统计显著性。但必须能被直接验证。

不同任务使用不同的收益证书，不能用一种统计阈值统管全部题型：

- 数据拟合：无泄漏样本外表现、校准、稳定性和实际差异；
- 机理/仿真：守恒、边界、观测回放、步长收敛和参数可辨识性；
- 优化/调度：同约束目标值、可行性、下界/最优间隙、小规模精确对照和多起点稳定性；
- 构造/证明：下界、可行构造、正确性证明和极端反例；
- 因果/政策：识别条件、对照口径、支持重叠、溢出检查和敏感性界。

### 6. 决策与主线门

复杂路线必须改变至少一项：题目必需输出、可行性判断、主要决策、关键误差界、稳健性结论或实质解释。若只带来微小分数变化而结论不变，采用更简单模型。

正文必须能用一条链讲清“题目→基准→基准缺陷→最小升级→结果→验证→结论”。复杂路线若迫使主线分裂、符号爆炸或需要大量题外假设，其收益必须足以抵偿阅读和验证成本，否则退回基准。

六项任一不通过，该复杂路线不得承担它所声称的主结论；可以删除，也可以明确降为探索或诊断。若不同路线分别服务于不同交付物或互相裁决，允许多条路线同时通过并保留。

## 四、何时停止加模型：硬门槛

满足以下任一条，立即停止新增候选：

1. 当前最简单路线已经生成所有必需输出、满足硬约束，并通过对应验证，且没有被证实的剩余缺陷；
2. 新候选没有独立题面触发证据，或只是在替换算法名称；
3. 新候选未达到预先冻结的实际改进阈值，改进不稳定，或主要决策与结论没有变化；
4. 有效样本、事件数、支持域、数据质量或参数可辨识性无法承载新增复杂度；
5. 最终留出集已被用来选择模型或调参；该留出集立即失去最终评测资格，停止“最优模型”声明，改用新的独立证据或降级措辞；
6. 新模型只是重复已有功能，不能产生新的必需输出或修复新的缺陷；
7. 新候选与已有路线功能重复，且没有新增结构证据、独立互证、稳健性价值或对结论的边际影响；模型数量本身不构成停止理由；
8. 现有不确定性来自题面缺失或数据不可识别，继续换模型不能消除它；此时停止并报告区间、情景或所需补充数据。

停止不是偷懒。停止时必须留下“停止证书”：保留的最简单路线、已满足的交付物、拒绝继续增加的理由、仍然存在但模型无法消除的不确定性，以及允许使用的结论等级。

若两条路线承担不同证明责任，例如一条给候选解、另一条给下界或独立复算，它们不因输出相近而被视为重复；只有证明责任也相同且没有新增证据时才触发停止。

## 五、防止多模型比较造成数据窥探

1. 建模前登记候选角色、主要指标、数据切分和升级阈值；不得看完测试表现后补写理由。
2. 区分搜索数据、选择数据和最终评价数据。所有特征筛选、预处理、模型选择和调参都属于训练过程。
3. 多候选或多超参数必须使用嵌套验证、时间外验证或主体外验证；最终数据只评一次。测试集一旦参与选择就不再是测试集。
4. 报告尝试过的候选总数和淘汰原因，不能只展示获胜者制造“必然优秀”的印象。
5. 数据太少无法留出时，使用完整嵌套重采样并报告不确定性；不得宣称已找到普遍最优模型。
6. 若同一数据上反复比较大量模型，优先采用“一标准误差/最简单稳定模型”思想：性能无实质差异时选复杂度更低者。

## 六、审计能力不等于求解能力

审计只能说明“哪里可能错、需要什么证据”，不能自动产生答案。主路线从审计升级为可执行求解，至少需要：

- 已定义变量、索引、单位和数据来源；
- 关键方程、状态转移、目标或判定规则；
- 完整硬约束和边界条件；
- 明确的输入、算法步骤、终止条件与输出字段；
- 至少一种可实际执行的求解出口；
- 与题目交付物对应的验证办法。

缺任何一项，只能标为“审计完成”或“路线草案”。没有运行或解析结果时，不得标为“已求解”；没有独立验证时，不得标为“已验证”。

## 七、严格区分描述、预测和因果

每个高价值结论在内部先标记为D、P或C：

### D：描述性结论

回答给定样本、时期和观测口径中“发生了什么、如何相关”。允许使用“观察到、相关、分布、差异”，不得外推未来，不得写“导致、提高、降低”。

### P：预测性结论

回答在明确目标群体、时间范围和信息条件下“对未见对象或未来能预测多好”。必须有无泄漏的样本外、时间外或主体外验证，并说明分布漂移和支持域。预测准确不证明变量是原因，也不自动证明据此干预有效。

### C：因果性结论

回答明确干预相对于明确对照会改变什么。必须给出干预、对照、对象、时间和结果构成的因果目标，并说明识别依据、混杂控制、支持重叠、干扰/溢出和敏感性。缺少随机化、可信准实验、可辩护结构机制或充分识别条件时，结论必须降为D/P或“模型情景”，不能使用因果措辞。

用预测模型做优化时，如果决策变量对结果的响应没有因果或机理支撑，只能写“在所设响应情景下的推荐”，不能写成现实干预必然改善。描述、预测、因果三类指标不得混成一个综合分数来掩盖证据等级。

## 八、论文主线按作用组织

正文只保留回答必需交付物和支撑关键可信度的内容。每个交付块应展示可信基准和所有真正必要的最终路线，并明确它们是串联、分支、互证还是集成关系。诊断挑战者在真正推翻、界定或显著增强主结论时可以进入正文；不发挥这些作用时再放入附录或淘汰记录。

以下内容必须删除或降级：没有题面触发的高级机制、未通过独立验证却承担最终结论的模型、没有互证或边界价值而重复表达同一关系的算法、只增加图表不改变结论的比较，以及无法解释的参数堆叠。反之，题目要求的多阶段组件、真实结构分支、必要互证和经独立验证有效的集成不得为了形式简洁而删掉。创新应写成“解决了什么问题并带来什么可验证变化”，不能只列模型名称。
