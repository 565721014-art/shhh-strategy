# 从这里开始：V27.1唯一入口

## 读取顺序

1. 读取 [V27入口](../v27_formal_problem_reader/从这里开始_给Codex.md)，继承完整读题、信息边界、方法裁决和验证能力；
2. 读取 [复杂度、证据与停止门](复杂度_证据_停止门.md)；
3. 读取 [往届34题防误删训练](往届34题防误删训练.md) 中与当前结构相近的保留/删减边界；只能迁移裁决逻辑，不能复制题目答案；
4. 若V27旧规则鼓励继续扩展，而V27.1停止门要求停止，以V27.1为准；若V27.1的简化会删除题面强制结构，则以题面和防误删规则为准；
5. 不读取、调用或引用任何本地数学建模相关Skill。

## 按必要性决定路线数量

不设固定模型数量上限。对每个“独立交付块”，所有保留路线都必须具有清楚且不重复的角色，例如：

- 提供公平参照的可信基准；
- 修复不同实质缺陷的候选路线；
- 裁决真实结构歧义的分支路线；
- 检查稳健性或推翻主结论的诊断路线；
- 分别完成不同分问或不同阶段交付物的串联组件。

这里的交付块指产生一个独立结论或决策的数学任务。预测→优化、标定→反演等必要串联组件不算为了比较而堆模型，但每个组件必须有不可替代的输入输出。即使多个算法承担同一功能，只要它们用于裁决尚未确定的结构、提供必要互证或经独立验证证明组合有实质收益，也可以保留；不允许的是没有新证据、新作用或新结论的重复堆叠。

## 执行顺序

题面与附件事实锁定 → 每问交付物 → 结论类型锁定 → 可信基准 → 发现基准的实质缺陷 → 检查题面触发与数据承载 → 预先冻结比较方案 → 允许所有通过准入门的必要升级 → 独立评价 → 按边际价值执行停止门 → 形成清晰但不强行单一化的论文主线。

若基准已经回答题目且没有可证实缺陷，必须停止加模型。若复杂路线没有改变硬约束可行性、主要结论、决策质量、稳健性或可解释性，退回较简单路线。

## 状态必须分开

- `理解锁定`：确认题目要求、信息、约束和结论类型；尚未建模。
- `审计完成`：找到误读风险、候选路线与验证方案；不等于已经求解。
- `路线可执行`：变量、公式/递推、约束、算法入口出口和输出格式齐全；尚不等于有结果。
- `求解并验证`：已有可复现结果且通过约束、基准和独立验证，才允许形成结果结论。

用户只要求思路时，可以停在“路线可执行”，但必须直说尚未数值求解；不得因审计很完整而写成“问题已经解决”。

## 默认向用户输出

只展示必要内容：题目核心理解、可信基准、升级触发、最终路线及其分工、停止理由、验证方法，以及描述/预测/因果结论的允许边界。被拒模型、重复审计和不改变结论的次要比较不进入主线；真正影响不同分问、结构裁决、稳健性或最终决策的多条路线应保留并说明关系。
